# Лабораторная работа №6

CUDA рассчитывает движение 150 заряженных частиц, OpenGL рисует их как текстурированные сферы. Частицы отталкиваются друг от друга, стен, камеры и пули; на них действует сила тяжести. На полу куба показана карта напряжённости поля.

## Сборка и запуск

Из корня проекта:

```bash
cd lab6
python3 -B build.py
./lab6
```

Для повторного запуска без изменений достаточно `./lab6` из папки `lab6`.

Нужны CUDA Toolkit, C++, OpenGL 2.1 с поддержкой старого конвейера отрисовки, GLU, GLEW и FreeGLUT. Окно OpenGL и CUDA должны работать на одном NVIDIA GPU. На гибридном ноутбуке программа выбирает NVIDIA через PRIME; заданные пользователем настройки сохраняются.

Скрипт настроен под текущий компьютер: GTX 1050 (`sm_61`), CUDA 12.8 в `/usr/local/cuda` и установленные системные библиотеки OpenGL. Он запускает одну команду `nvcc`; все пути и параметры видны в [build.py](build.py). Для другой архитектуры нужно изменить `-arch=sm_61` в скрипте. Необходимые заголовки OpenGL сохранены в `include/`; эту папку нужно оставить для повторной сборки.

Все настройки находятся в [lab6.cu](lab6.cu): число частиц — 150, карта поля — 256×256, seed — 6. Параметров командной строки у программы нет.

## Управление

| Действие | Клавиши |
| --- | --- |
| Вперёд, назад, влево, вправо | W, S, A, D |
| Вверх, вниз | E, Q |
| Повернуть камеру | Двигать мышью, удерживая правую кнопку |
| Выстрелить по направлению взгляда | Левая кнопка мыши |
| Пауза / продолжение | Пробел |
| Вернуть частицы в начальное состояние и убрать пулю | R |

Курсор не захватывается; поворот камеры работает при зажатой правой кнопке. Камера может летать за пределами куба и двигаться во время паузы. Пуля одна: новый выстрел заменяет предыдущую.

## Модель и устройство программы

Куб: `x,y ∈ [-a,a]`, `z ∈ [0,2a]`. Параметры задания: `a=15`, `ε=0.001`, `w=0.99`, `K=50`, `dt=0.01`, `g=20`, заряды частицы, камеры и пули — `1`, `30`, `50`. Радиус сферы — `0.35`.

Ускорение от каждого заряда: `K·qi·qj·(pi−pj)/(‖pi−pj‖³+ε)`. Добавляются аналогичные силы от стен и вертикальное ускорение `−g`. Затем `v_next=w·v+acceleration·dt`, `p_next=p+v_next·dt`. При перескоке через стену центр ограничивается границей с учётом радиуса, наружная скорость отражается с коэффициентом `0.5`.

Начальные скорости нулевые, центры выбираются случайно внутри куба с отступом радиуса от стен. Направление взгляда: `(cos(yaw)·cos(pitch), sin(yaw)·cos(pitch), sin(pitch))`. Скорость пули равна этому вектору, умноженному на `10`; стартовое положение — `camera+bullet_velocity`. Пуля движется равномерно и проходит сквозь стены.

Карта поля: `E=K·Σ q/((xp−x)²+(yp−y)²+(zp−0.75)²+ε)`. В сумму входят частицы и активная пуля. Координаты пикселей покрывают весь пол: `x=(2i/(size−1)−1)·a`, аналогично для `y`. Цвет — `RGB=(0,0,min(E,255))`, как в задании.

Основные шаги программы:

1. Один поток CUDA рассчитывает одну частицу обычным циклом по всем соседям. Старые и новые положения хранятся в двух массивах на GPU; после шага массивы меняются ролями.
2. CUDA переносит вершины заранее рассчитанного шаблона сферы в положения частиц и записывает их в общий с OpenGL VBO.
3. Отдельное ядро CUDA рассчитывает пиксели поля в общем PBO. OpenGL переносит их в текстуру пола через `glTexSubImage2D`.
4. OpenGL рисует пол, рёбра и сферы обычным конвейером с освещением и текстурой. Перед отрисовкой ресурсы освобождаются из CUDA.

Положения и пиксели не копируются каждый кадр через CPU. Таймер GLUT вызывает один шаг `dt=0.01` примерно каждые 10 мс. При высокой нагрузке моделирование может идти медленнее реального времени.
